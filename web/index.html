The alert is never where the bug is.

Rootpath gives your AI agent a FalkorDB graph of your services, deploys, feature flags, owners and past incidents. It follows a failure to where it starts, fixes it, checks the fix, and remembers.

How it works

      
The service that alerts is rarely the one that is broken. Rootpath finds the broken one by walking the graph, not by reading every log.

      

        
    
          
  1. Find where it startsWalk the call graph down from the alert to the deepest unhealthy service. Changes off that path are ruled out.
    2. 
          
  2. Check memoryRead that service's logs, and find past incidents with the same cause and what fixed them.
    3. 
          
  3. Act, dry run firstRoll back, restart or turn off a flag. A hook blocks any real action that was not dry-run.
    4. 
          
  4. VerifyWait until the alerting service is healthy twice in a row. If not, rank again.
    5. 
          
  5. Page and rememberPage whoever is on call, and store the incident with its root cause for the next agent.
    6. 
        


// one FalkorDB graph
(:Team)-[:OWNS]->(:Service)-[:CALLS]->(:Service)
(:Person)-[:ON_CALL_FOR]->(:Team)
(:Flag)-[:AFFECTS]->(:Service)
(:Deploy)-[:CHANGED]->(:Service)
(:FlagChange)-[:TOGGLED]->(:Flag)
(:Incident)-[:ROOT_CAUSE]->(:Change)
(:Incident)-[:RESOLVED_BY]->(:Action)

// step 1, roughly
MATCH p = (:Service {name: $alerting})-[:CALLS*0..6]->(d)
RETURN d.name, min(length(p)) AS hops
